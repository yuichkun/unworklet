Diagnostic mechanism (schema 2)
  The dedicated config selects the exact original test, retry=0, and applies
  in-memory transforms only to worklet.ts, client.ts and the original test.
  Production files, emitted WASM, original fixture, 32 quanta, 2 rAF and
  expect(observed).toBe(42) remain unchanged on disk and in their assertions.
  The observation is followed immediately by recording and a synchronous copy
  plus Object.freeze of the main array, before any new await or disposal.
  Subsequent deliveries cannot enter that frozen observation snapshot.

  Worklet: preallocated Float32Array(128), 15 records of 8 numbers and 8 header
  numbers: [54124, count, dropped, successfulProcessCount, 0,0,0,0].
  Records: [code,currentFrame,value,version,a,b,c,d].
    1 ready-send attempt; 2 listener registered; 3 start returned.
    4 queued payload: value; a=ring, b=queue length.
    5 injected payload: value; a=ring, b=head after injection, c=tail before DSP.
    6 WASM returned: live counter; a=head, b=tail after DSP.
    7 publish post returned: live counter/version; a=sample counter,
      b=published bits low16, c=bits high16, d=slot index.
    8 final process: live counter/last version; a=queue length,b=head,c=tail.
  Event 6 alone does NOT establish consumption. The decoder only reports
  consumptionConfirmed when one main send of 42, a preceding queue receipt,
  one matching injection, same-frame WASM return, matching head, tail advance
  by one to head, and the expected live value 42 all correlate.

  Main: preallocated Float64Array(128), 24 records of 5 numbers at offset 8.
  Header count, dropped, six zeros; records [code,value,version,slotOrRing,seq].
    1 ready received; 2 send; 3 valid publish received; 4 mirror written;
    5 render resolved; 6 original observation; 7 createNode returned.
  Link payloads/versions; local sequence is not a cross-thread clock.

  Markers prove execution of diagnostic code, not merely its server transform:
    test: createRetention invoked from the transformed test, uwk-diag-test-v2:<runId>;
    client: evaluated transformed module, uwk-diag-client-v2:<runId>;
    worklet handshake: uwk-diag-worklet-v2:<runId> + bounded 128-element trace carried
      in the EXISTING ready/init-error message, captured by the existing client
      handshake handler. No extra port listener or message is created.
    worklet final: header 54124 in the final-quantum sideband plus event8/frame3968.
  A create failure may provide only main/test/client evidence. No received
  handshake means worklet application is unknown, not disproven.

Failure retention and exception priority
  A try/catch/finally covers create/render/rAF/observation/assertion. Primary
  exceptions are rethrown by identity, including a thrown undefined. finish()
  snapshots whatever is available BEFORE cleanup, records disposal errors, and
  attempts one bounded export even if dispose throws. Export failure is logged
  with bounded text and cannot replace a primary or disposal error. After an
  otherwise passing scenario, export failure still fails diagnostic execution.
  No original wait, render duration, assertion, or test timeout is extended.
  The only new awaited RPC, bounded to100ms, exports already-captured data after the observation
  or failure. It does not request worklet delivery or read the mirror again.
  Existing Vitest onTestFailed provides a best-effort runner-timeout fallback.
  A one-attempt latch prevents double export; late-created nodes are disposed,
  and closed-run checks prevent resuming the scenario after that cutoff.
  If the browser is dead, this hook may never run. Complete capture is NOT promised.

  Before scenario execution, config validates a new absolute output path and
  absent sidecars. onInit writes an exclusive <=16KiB manifest. The exporter
  writes an exclusive <=64KiB trace. onTestRunEnd writes <=16KiB runner metadata:
  run id, reason, at most two module states, target result with one bounded error,
  and at most two bounded unhandled errors. It records missing/incomplete trace
  independently of whether the original assertion passed. Incomplete diagnostic
  output makes the run exit nonzero without changing the original assertion.
  If the runner itself is killed, only the pre-run manifest may remain; absence
  of completion metadata means an interrupted/unknown run, not no delivery.

Strict decoding
  Require schema2 and test/client/worklet markers; both main/worklet arrays
  must be exactly128 elements with finite numeric elements. Counts must be
  finite integers in0..24 and0..15 respectively; drops strictly numeric0;
  successfulProcessCount32; reserved headers and unused records zero.
  Validate event codes, integer frame/version/index fields, record-specific
  shapes and main sequence. Require exactly one terminal event8/frame3968
  and exactly one terminal main observation matching the recorded observed value.
  Require the main snapshot to be frozen at observation and recording enabled.
  Missing, malformed, oversized, partial or overflowed trace is incomplete,
  with negativeEvidenceAllowed=false and consumptionConfirmed=false. No timeline
  or no-delivery inference is emitted from incomplete trace.
  Even complete trace only permits statements up to the main observation and
  final process cutoffs, never about permanent loss or later delivery.

Perturbation and limits
  The record arrays/views are preallocated. DSP recording uses bounded scalar
  stores; there is no console I/O, added port task, timer, rAF, polling or ack.
  The existing ready/init-error envelope gains a marker and one 512-byte trace
  clone before rendering; this costs startup serialization and is not free.
  Per-process counters/branches and the final 128-sample copy also cost time.
  The main observation freeze copies128 elements synchronously AFTER reading
  observed, so it cannot change that captured value, but it can affect later work.
  UWK_DIAG_RECORD=0 still evaluates call arguments (state/header reads), performs
  instrumentation branches, allocations, handshake fields and final copy. It is
  an instrumented comparison, NOT a zero-overhead or uninstrumented baseline.
  No on/off runs were performed. Disabled recording yields incomplete diagnostic
  status, as expected; do not interpret it as negative delivery evidence.
  Worklet receipt after final process is unknown; incomplete handshake-only
  snapshots do not cover later ingress or publication. Main receipt may also
  occur after observation and is intentionally excluded from the frozen array.

Interpreting a real failing trace
  No event4 by worklet cutoff: ingress not observed during rendering. Late
  delivery vs another ingress problem remains unresolved.
  Event4 but no event5: inspect frame and cutoff; queue was not consumed by a
  later process call. Use header process count and event8 queue/head/tail.
  Event5/6 with live42 only after frame3072: 32-quanta publication window can
  explain stale mirror without proving #171 caused the historical CI failure.
  Event6 live42 by frame3072 but event7 publishes0: inspect publish scheduling
  and WASM published slot; distinguish live value from decoded published bits.
  Event7 published42/versionN but no main event3 before event6 observation:
  downstream delivery/listener timing is implicated in THAT captured failure.
  Main event3 sees42 but event4/observation stays0: inspect mirror application
  and subsequent versions using main local sequence.
  Success, missing artifact, or invalid trace never closes the regression.

Run identity and source evidence
  A fresh UUID is generated per diagnostic config/server instance and embedded
  in the test, client and worklet transformed source. Returned marker strings
  must all carry that same UUID. Server-added runId is not sufficient alone.
  Each of those three transform hook calls hashes its input source and the exact
  code it returns (SHA-256), recording role, repository-relative sourcePath,
  runId, sourceHash and transformedHash in the manifest. This is hook output,
  not a claim about the final code after Vite's subsequent transforms.
  The original worklet.ts/client.ts/test sources are thereby covered at the hook.
  Manifest updates use an exclusive pending file and atomic rename. Identical
  repeated transforms are deduplicated; conflicting results mark that role
  ambiguous instead of replacing the first evidence. At most three roles exist.
  Trace captures the current manifest; decodeFile also loads the sibling manifest
  and verifies runId and all three hash records match it. Missing, stale,
  malformed or ambiguous evidence is incomplete. Exported artifact validation
  reports incomplete without discarding the available trace.

Export deadline
  Only post-observation/failure export receives a100ms Promise.race deadline.
  Its timer is cleared on success, rejection and timeout. A pending write cannot
  keep finally waiting indefinitely. The original primary/dispose exception
  keeps priority; a passing scenario fails with DiagnosticExportTimeout.
  Bounded secondary error is stored in task.meta.uwkDiagnosticExportFailure;
  the reporter copies it into runner metadata independently of browser trace.
  No new render/rAF/readback is introduced and test/runner deadlines are not
  extended. An already-expired runner deadline or dead browser can still prevent
  capture; that existing limitation is not overridden. The underlying RPC is
  not cancelled and may finish later, but no retry or later observation occurs.
  Unit coverage includes never-resolving write, finite completion, exact primary
  identity, secondary timeout and timer clearing. No native execution occurred.
